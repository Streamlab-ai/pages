Quick Reference
Getting started
Two steps to launch, one manual step mid-pilot

Every new pilot cohort starts with the same two actions from Matt. WF1 through WF3 then run automatically. Before WF4's weekly heat map can send, one Pipedrive field has to be updated by hand per participant — see step 3 below.

1
Matt's Action

Upload the Cohort Roster to SharePoint

Open the Pilot Roster Template ↗ in SharePoint and add each participant to the PilotRoster table.

Columns must be entered in this exact order — WF1 reads each row by column position, not by header name, so a column out of place will corrupt every row behind it:

  1. PilotName
  2. CohortID
  3. FirstName
  4. LastName
  5. Email — required, must contain @
  6. Role / Title
  7. Company
  8. ChampionName — the leader who receives Monday reports
  9. ChampionEmail
  10. PilotStartDate — format YYYY-MM-DD
  11. Notes — optional

Assign a unique Cohort ID that will identify this group across all data — for example, SF-2026-07 for Sioux Falls July 2026. Never reuse an ID.

2
Matt's Action

Set the Trigger in Pipedrive

Open the client's Deal in Pipedrive. Set Stage → Pilot Active and flip Confirm Pilot Cohort → Yes. WF1 fires the moment both conditions are true on the same deal update.

✓
Automation Active

WF1 → WF2 → WF3 run automatically from here

WF1 imports the roster and creates Pipedrive records. WF2 sends the pre-filled diagnostic link every weekday at 8AM Central to anyone marked Not Sent. WF3 runs every Friday at 10AM Central — it matches completed responses back to Pipedrive and sends a reminder to anyone still unresponded 3+ days after their initial send.

!
Matt's Action — Required

Manually advance participants to "Practice" phase

Nothing in WF1–WF3 ever changes a participant's Current Phase field — it's set once at import (Diagnostic) and stays there. WF4's Friday heat map send only pulls people where Current Phase = Practice, so once the diagnostic period ends, Matt needs to open each participant's Person record in Pipedrive and set Current Phase to Practice himself. Nobody is included in the heat map until this is done.

✓
Automation Active

WF4 and WF5 take it from there

WF4 sends the weekly leader heat map every Friday at 8AM Central and delivers the Monday leader report at 8AM Central. WF5 checks every Monday at 10AM Central for cohorts with both pre- and post-diagnostic data ready, then assembles the Executive Brief data package and notifies Matt/Tamien.

Cohort ID convention
The naming rule that keeps everything organized

The Cohort ID is embedded in every form URL sent to participants. It's the primary key that flows through Pipedrive, SharePoint, and all five workflows. Use a consistent format so data stays clean across multiple cohorts.

Format — [City or Company]-[YYYY]-[MM]

One ID per cohort. Assign it when you build the roster. Never reuse an ID.

SF-2026-07
Sioux Falls event cohort, July 2026
KC-2026-07
Kansas City event cohort, July 2026
ACME-2026-08
ACME Corp pilot, August 2026
Monitoring
See who's responded and who hasn't

The system tracks every participant's status in real time. These are the four Pipedrive filters the workflows themselves rely on — the same ones give Matt an immediate view of where each cohort stands.

Pre-Diagnostic Not Sent Filter 171
Contact Type = Pilot Respondent · Pre-Diagnostic Status = Not Sent
The queue WF2 sends against each weekday morning. If someone stays stuck here, WF2 hasn't reached them yet.
Use this to: confirm new imports are in the send queue.
Pre-Diagnostic Sent — No Completion Filter 172
Contact Type = Pilot Respondent · Pre-Diagnostic Status = Sent
Everyone who received the link but hasn't submitted. This is also the pool WF3 pulls reminder candidates from every Friday.
Use this to: identify who needs a manual nudge, and confirm WF3's reminders are firing on schedule.
Practice Phase Active Filter 173
Current Phase = Practice
WF4 pulls this exact filter every Friday to build the heat map send list.
Important: this filter is empty until Matt manually sets Current Phase = Practice on each participant. See the Launch tab, step 3.
Post-Diagnostic Sent Filter 174
Post-Diagnostic Status = Sent
Used by WF5 to confirm a cohort's post-diagnostic has gone out before it starts checking for completed pre+post data pairs.
Use this to: check whether the post-diagnostic round has been sent for a given cohort.
Reading the data
Where to find responses and counts

Pipedrive shows individual status. SharePoint Excel files hold the actual response data and per-cohort counts.

📊

Reading diagnostic responses

  1. Open Ripple Diagnostic Responses ↗
  2. Filter the Cohort ID column to your cohort
  3. Filter the Phase column — Pre or Post
  4. Copy/paste into AI tool or export to CSV
🔢

Getting a per-cohort count

  1. Open Pilot Roster Template ↗ — use the Send Log tab
  2. Filter by the Cohort ID column
  3. Row count = total participants in that cohort
  4. Note: Pipedrive does not display group totals
Data integrity
Why cohorts never get mixed up

Three layers of protection ensure that a participant who appears in two separate cohorts generates two independent, correctly labeled records — never a merge conflict.

WF1
Cohort ID baked in at import. Every participant gets their Cohort ID the moment their roster row is processed — written to their Pipedrive Person record immediately.
WF2
Prefilled URL per person. WF2 generates a unique form URL for each participant with their Email and Cohort ID embedded as hidden fields. They never type it — it arrives pre-populated.
WF3
Email + Cohort ID matching key. WF3 uses both fields together — not email alone — to match submissions back to Pipedrive records. One person in two cohorts gets two correctly labeled entries.
Pipedrive custom fields
What gets tracked on every participant

These custom Person fields are set automatically by the workflows, with one exception noted below. Matt can view and filter on any of them directly in Pipedrive's People list view.

Field Values & Description
Contact Type
Single option
Pilot Respondent · Sales Contact
Set to Pilot Respondent for every participant added via WF1.
Cohort ID
Text
The unique identifier for this cohort (e.g. SF-2026-07). Set at WF1 import. Used as the matching key in every downstream workflow.
Associated Pilot
Text
Name of the pilot program this participant belongs to.
Pre-Diagnostic Status
Single option
Updated automatically as WF2 and WF3 run. There is no separate "reminder sent" field — a reminder simply moves this status to Reminder Sent.
Not Sent Sent Reminder Sent Completed Needs Review
Post-Diagnostic Status
Single option
Mirrors Pre-Diagnostic Status for the post-practice round. Checked by WF5 (via Filter 174) before assembling the Executive Brief.
Not Sent Sent Reminder Sent Completed Needs Review
Pre-Diagnostic Sent At
Date
Timestamp written automatically when WF2 sends the prefilled form URL. There is no corresponding "completed at" timestamp — completion is tracked only by the status value above.
Current Phase
Single option
Diagnostic (set automatically by WF1 at import) · Practice · Proof · Complete
Diagnostic Practice Proof Complete
⚠ Does not advance automatically. Matt must change this to Practice by hand — WF4 will not include a participant in the Friday heat map until this is set.
⚠

Known limitation — Current Phase

WF1 sets Current Phase to Diagnostic when a participant is created and nothing after that ever updates it. WF4's participant list is built entirely from Pipedrive Filter 173 (Current Phase = Practice), so heat maps silently send to nobody until Matt updates each participant's record. This is the one point in the pipeline that isn't yet hands-off.
